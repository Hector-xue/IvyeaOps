# ADR-0032：模型把同一段整段重抄时，只留最后一份

- 状态：已采纳
- 日期：2026-09-02

## 背景

[ADR-0027](./0027-a-turn-reads-as-it-happened.md) 把一轮任务铺成「说一段 → 做几件事
→ 再说一段」。它成立的前提是一条模型行为假设：**工具跑完之后模型接着往下说**。

有的模型不这么干。实测 `z-ai/glm-5.3-flash`：每次工具调用之后，它把已经说过的那张
表从头到尾再抄一遍，只在末尾添一行新的。三次工具调用之后，同一张表在页面上出现了
三遍，一遍比一遍长。用户的原话是：**「总不能增加一条新内容就把整个都输出一遍吧」**。

这不是渲染缺陷 —— 那三段话是模型真的分三次说出来的，存档里也是三条真实的 assistant
消息，所以刷新之后同样重复。界面只是太老实。

agent 侧其实发了边界信号（`answer_reset`，reason=`tool_call`），但那个信号只说"新的
一稿开始了"，说不出"新的一稿是不是把旧的重写了一遍"：工具前的开场白（该留）和整段
重抄（该丢）走的是同一条 reason。

## 决策

在**渲染层**判重：一串正文里，如果后面某一段把前面某一段**整段重抄了一遍**，就只留
最后那一份。判据是 `lib/restatement` 的**逐字前缀**——

> 归一化空白之后，后一段一字不差地以前一段开头，且前一段不短于 40 字。

直播（`TurnBody.blocksOf`）和刷新后恢复（`lib/sessionRestore`）用同一条规则，两边看到
的必须还是同一个东西。被作废的那一格如果挂着执行过程就留下壳 —— 工具是真跑过的。

## 理由

**为什么不在 agent 侧改 reason。** 要让 agent 说得出"这一稿是重写"，它得自己比较前
后两稿 —— 那正是这里做的事，只是换个地方做。而且 reason 的语义是"边界"，不是"关系"；
让它兼职判重，CLI（不接这个回调）也得跟着改。放在渲染层，改动只影响看得见的那一层。

**为什么不用相似度 / 编辑距离。** 这里做的是**删掉用户已经看过的内容**，判错的代价
不对称：漏掉一次合并只是多占半屏，吞掉一段真话是丢信息。所以只认最硬的证据——逐字
重合。模型改了一个字就不算重述，宁可漏。

**40 字的下限**同理。短句的前缀撞车太容易（"好的，我看一下"谁都可能再说一次），几十
个字以上的逐字重合不可能是巧合。

**为什么不干脆退回"一轮只显示最后一段"。** 那会把 ADR-0027 整个推翻：绝大多数模型的
"边做边说"是真的旁白，不是草稿，砍掉它就回到了"一大堆叠在一起"。

## 后果

- 表现正常的模型一个字都不受影响：三段真的不同的话，没有一段是另一段的前缀。
- 重抄型模型只剩最后最全的一份。直播时会有一个短暂的过渡：新一稿还没长到超过旧稿
  之前，两稿并存；一旦盖过去，旧的那份消失。**不能反过来**（保留长的那份），那会让
  正在流式输出的字看不见，界面像卡住了。
- 判重要逐段比字符串，而正文每个 token 都会重渲染 —— `blocksOf` 因此挂了 `useMemo`。
- 验证台补了 `?restate=1` 桩（三稿：4 行 → 5 行前缀扩写 → 一字不差的完全重复），
  没有它这个毛病在验证台里复现不出来，规则也就无从验证。
