# ADR-0020 · 附图的文字版归属于 user 消息，不再塞进 system

- **日期**：2026-08-21
- **状态**：已采纳
- **依据**：任务台会话 `20260821-171923-592-d5bc` 的真实存档 + IvyeaAgent v1.15.3

## 背景

任务台的图**不进模型**：ops 侧先用配好的视觉模型把图读成文字，再随这一轮带下去
（图片本体只以 `ivyea-ref://` 句柄留在服务器上，供图生图取原图）。

这段文字此前挂在 `payload["system"]` 上。而 agent 那边的 system 是**每轮重建**的，
落盘时还会被本轮这份整个覆盖（`sessions.append_turn`）。后果是一次贴图问答里，
"图里是什么"只在贴图那一轮存在：

- 用户贴图问"这张图里面是什么"，模型答得完全对；
- 下一轮问"你是通过什么识别图片的"，模型手里一个字都没有，于是**否认自己收到过图**，
  还把上一轮如实的描述说成是自己编的；
- 会话存档里同样看不出用户发过图，刷新之后界面上那一轮只剩一句光秃秃的问题。

同一轮里还暴露出输入框的问题：图要等**整轮跑完**才清（中止/断链的分支直接 return，
根本走不到那行清理），一轮几分钟里图一直挂在输入框上，看起来像没发出去。

## 决策

附图的文字版走新的 `attachments` 字段（`[{kind,name,ref,by,text}]`），由 agent 并进
**这一轮的 user 消息**；ops 只在对方是老 agent（< v1.15.3）时才退回塞 system。
展示端按 `[用户附图` 这个标记把它从气泡里截掉，气泡里给的是**原图缩略图**
（`GET /api/assistant/image/ref/{id}`，从存档里的句柄取回原图）。

输入框里的图和 `@` 引用改成**发送那一刻**就清空，和文字一起。

## 理由

- **不选"把描述拼进 `message`"**：`message` 还要拿去做路由判定、知识检索、技能匹配和
  会话标题 —— 一段几百字的图片描述会把这四件事一起带偏。
- **不选"让 agent 自己收图"**（`payload["images"]` + agent 的视觉三档链）：那条链在
  agent 侧另配视觉模型，这台机器上恰好两边都配着，但用户机器上很可能只配了一边；
  ops 这条链是 Listing、技能商店一直在用的那条，可靠性有据可依。真要合并成一条，
  是另一个决定，不该混在这次修复里。
- **不选"图片本体进存档"**：几百 KB 的 base64 写进会话 JSON，每轮读写整份历史都要背着它。
  句柄 + 一个取图出口便宜得多，代价是句柄只保留最近 200 张，更早的历史图会失效
  —— 界面上那一格直接摘掉，不留碎图。

## 后果

- 附图内容跟着历史和存档走，多轮追问不再失忆；模型也被明确要求不许否认收到过图，
  并说得出是哪个视觉模型代读的。
- 会话记录里能看见自己发过的图（本次会话是 data URL，历史是句柄取回的原图）。
- 上下文里多了一段常驻文本：一张图的描述通常几百 token，四张图会明显占位。
  真嫌重时应该做的是压缩描述，而不是退回"只在当轮有效"。
- 句柄过期（超过最近 200 张）的历史轮次只剩文字，不再有缩略图。
