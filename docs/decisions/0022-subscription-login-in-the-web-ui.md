# ADR-0022 · 订阅制模型的登录搬进网页，且只给管理员

- **日期**：2026-08-21
- **状态**：已采纳
- **依据**：用户提问「有些订阅会员还是得去 IvyeaAgent CLI 登录吗？有些人不会用 CLI」

## 背景

模型接入分两类。填 API Key 的那类，系统配置里给个输入框就完事；而订阅制的五家
（Claude 订阅、OpenAI Codex、Gemini Code Assist、Qwen、GitHub Copilot）要走一次
OAuth，此前唯一的入口是 IvyeaAgent 的命令行 `ivyea model auth <id> --login`。

IvyeaOps 的目标用户是亚马逊运营，不是工程师。"接不上自己已经付过钱的订阅"这件事，
卡住的正好是最不该被卡住的那批人。

## 决策

1. IvyeaAgent 把登录开成 HTTP（见 agent 侧 ADR-0015），IvyeaOps 透传并做成引导式界面。
2. 面板放在「系统配置 → 订阅登录」，**仅管理员可见，后端端点一律 require_admin**。
3. 面板顶部常驻一条提醒：这里登录的账号存在服务器上、由 agent 全局共用，全站所有
   对话和定时任务都会用它的额度；各家订阅条款通常限个人使用，是否合规由部署者判断。
4. 任务台模型选择器里「未配置密钥」那一组，这五家的副标题改成「去登录」。

## 理由

**为什么只给管理员**：token 落在服务器的 `~/.ivyea/auth.json`，agent 全局共用 ——
谁登录，全站就烧谁的额度。这不是普通用户该按的开关。后端端点也真的挡住了，前端
隐藏只是为了不把一个按下去必然 403 的按钮摆在人面前。

**为什么把提醒做成常驻的琥珀色横幅而不是灰色小字**：它说的是"你这一下会让全站都用
你的额度"。这种话写成脚注等于没写。

**为什么不做成"每个用户绑自己的订阅"**：agent 是单进程单套凭据的，要做多租户得把
凭据按用户分区、并让每一轮对话带上是谁在问 —— 那是另一个量级的改造。当前部署形态
（自托管、一个小团队共用一台）下，单租户 + 说清楚，是诚实且够用的。

**Gemini 的回调走不通怎么办**：它默认要在本机起 `127.0.0.1:8085` 的回调服务，远程用
时那是用户自己的电脑而不是服务器，必然连不上。但浏览器地址栏里带着 `?code=…`，
把整条 URL 粘回来即可。界面上把这句"跳转会失败，这是正常的"明确写出来 —— 不写的话
用户看到打不开的页面只会以为功能坏了。

## 后果

- IvyeaOps 与 IvyeaAgent 之间多了一处版本耦合：这个面板需要 agent ≥ v1.15.5。
- Copilot 的 token 写进 `COPILOT_GITHUB_TOKEN`，不碰 `GH_TOKEN` / `GITHUB_TOKEN`
  （那是 gh CLI 和 CI 在用的）。退出登录同理，只清自己那一个。
- 设备码轮询在浏览器里跑，用 ref 驱动的循环、由按钮点击启动，**不放在 effect 里**：
  effect 里 setState 会让依赖变化、cleanup 先跑，回调全被作废 —— 任务台的模型面板
  刚栽过这个跟头（见本次 5a7cbeb 之前那几个提交）。
