# ADR-0004 · 五步开发流：未经确认不得跳步写代码

- **日期**：2026-05-12
- **状态**：已采纳，至今强制执行
- **依据**：Hermes 会话，2026-05-12 09:25

## 背景

项目全程由 AI 编码。前三周反复出现同一种浪费：AI 拿到需求直接动手，方案没想清就改文件，
改完发现理解错了要返工，或者改坏了别的地方。作者也无法在中途判断它到底要干什么。

## 决策

作者当天把它定成永久规则，原话：

> 现在开始我给你加一条设定，加入记忆中，永远不要删除；收到开发任务后，必须按以下步骤执行：
> 1. 输出需求理解和边界确认
> 2. 输出技术设计方案
> 3. 复核方案并优化
> 4. 列出实现任务列表
> 5. 逐步执行，每步完成后汇报
>
> 未经确认不得跳步直接写代码。

## 理由

- 前三步都很便宜，第五步很贵。把错误挡在便宜的地方
- 「复核方案并优化」是关键的一步 —— 第一版方案往往能跑但不够好，让它自己再过一遍
- 作者需要一个能在动手前介入的节点，否则只能等做完了才发现方向错了

## 后果

- 此后所有会话（不论 Hermes / Codex / Claude Code）都按这个流程走，「按开发五步法执行」
  成了高频指令
- 派生出配套要求：**动手前必须核实消费方契约、真实数据源、运行环境**，因为「理解需求边界」
  如果建立在猜测上，后面四步全是错的
- 计划模式（plan mode）天然契合这个流程，成为默认工作方式
