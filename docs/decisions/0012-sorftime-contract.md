# ADR-0012 · 外部数据源的真实契约要用测试钉住

- **日期**：2026-07-29
- **状态**：已采纳
- **依据**：提交 `fix(sorftime): 参数名改 snake_case，修市场调研拿不到数据`

## 背景

市场调研板块拿不到数据。排查出 Sorftime MCP 的几条真实行为，全都和文档或直觉不一致：

- 参数名必须是 **snake_case**，传 camelCase 会被**静默丢弃**（不报错，只是拿不到数据）
- 返回结构是 `{doc, data}`，字段名是英文
- `product_report` 是废接口
- **失败装在成功响应里** —— HTTP 200，错误藏在 body 里

## 决策

在自己这一侧收口：统一的 `normalize_args`（参数名归一）+ `unwrap`（解信封）+ `rows`（取数据行），
并写**守卫测试**钉住这几条契约。

同时前端消费方也要对齐新信封 —— 只改后端会导致报告出现两遍。

## 理由

- 静默失败是最难查的一类 bug，必须在自己的边界上转成显式错误
- 外部服务的契约会变，测试是唯一能在它变的时候立刻告警的东西
- 「改了后端忘了前端」在这次和后来多次重复出现，所以**改契约必须同时检查消费方**

## 后果

- 确立一条通用做法：接入任何外部数据源，先实测真实返回，再写守卫测试，最后才写业务逻辑
- 派生出更一般的纪律：落地前先核实消费方契约、真实数据来源、运行环境（库版本 / CLI 行为），
  不要基于文档或印象写代码
