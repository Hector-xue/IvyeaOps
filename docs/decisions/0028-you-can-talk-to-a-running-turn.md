# ADR-0028：任务跑着的时候不该闭麦

- 日期：2026-08-28
- 状态：已采纳

## 背景

任务台的输入框在一轮跑起来之后就废了：发送键整个变成「停止本轮」，`send()` 里
第一行是 `if (!text || busy) return`，Enter 被吞掉。于是一轮几十分钟里，用户能做的
只有两件事 —— 干等，或者掐掉重说一遍（前面几十分钟的上下文一起作废）。

而人最想说话的时刻，恰恰是**看着它跑偏的那一刻**。

更别扭的是那颗「停止」：它做的事从来不是掐掉任务。`stop()` 只 abort 本地那条 SSE
连接，轮次在 agent 那边照跑（这一点在 `attachLiveTurn` 的注释里写得明明白白）。
所以它占着主键的位置，做着一件与文案不符的事。

同一批问题还有三条：

- 模型拿不准时要么自己猜一条路跑到底，要么把问题写进回答然后结束这一轮；
- 左栏看不出哪条会话正在跑（那枚绿点的判据是"10 分钟内更新过"，是"最近"不是"在跑"）；
- 没有时间：不知道自己什么时候发的、它什么时候做完的、跑了多久。

## 决策

### 一、忙碌时的主键仍然是发送

`busy` 时输入框和发送键都保持可用，按下去 = **追加给正在跑的这一轮**
（`POST /chat/inject`）。停止降级成旁边一颗次级按钮 —— 并且现在它是**真的停止**
（见下）。

投递有两种去处，界面上分得很清：agent 收下（`accepted`）就是"已插入本轮"，
没有活轮就是"本轮结束后发"，队列条上写着哪一种。**说出去的话到底进没进去，
必须有准信** —— 这是这条改动的全部意义，含糊的反馈比不能发更糟。

认领用 agent 回的 id，不用文本比对：事件里的文本经过脱敏，比文本会漏认，
而漏认的后果是同一句话被发两遍。一轮结束时，凡是没收到 `injected` 回执的，
一律当成下一轮发出去。

### 二、停止真的停

那颗按钮原本只 abort 掉本地那条 SSE，轮次在 agent 那边照跑照烧 token。现在先
`POST /chat/cancel`、等 agent 的 `cancelled` 回执把这一轮收尾，再让流自然结束
（6 秒没等到才断流兜底，且只掐**这一轮那个** controller —— 用户停完马上又发一句的话，
`abortRef` 早换成新一轮的了）。

三条路都要说实话：停住了、这条会话本来就没在跑、停不掉（老 agent / 没连上）。
最后一种必须明说"后台可能还在跑" —— 显示"已停止"而它其实还在花钱，比不给这个
按钮更糟。

停掉之后还有两件顺带的事：排队待发的追加指令一并取消（任务都不做了），以及不跑
跟进建议（那是又一次模型调用）。

### 三、选项卡就地渲染，倒计时说实话

`question_request` → `QuestionCard`。它和审批卡长得像，但语义相反，所以两处措辞
必须不同：审批卡是"到点自动取消"，选项卡是"**到点按推荐项继续**"。推荐项当场标出来
—— 那是"我不选的话会发生什么"的答案，不标等于把默认值藏起来。

收尾时那句"这一轮有 N 项是替你定的"由**界面自己画**（读 `final.auto_decisions`），
不指望模型在总结里提。理由同 `memory_recall`：确定性的信号才敢让用户依赖。

### 四、正在跑 = 真的在跑

左栏的闪烁标记读 `GET /chat/live-sessions`（agent 内存里的活轮登记），5 秒一次、
页面切后台就停。**agent 问不到时保持上一次的显示**，不清空 —— "问不到"不等于
"没有在跑的"，清空会让正在执行的会话看着像已经停了。

### 五、时间取服务端的，不自己掐表

发送时刻、结束时刻、本轮时长都来自 agent 的 `turn_times`/`final`。前端自己记的数
在断链、换标签页、换机器之后一个都不剩，而且一轮跑完前端还会重新拉一次存档、
把内存里的数冲掉。

一个刻意的例外：**只在这一轮真的结束了才写"结束于"**。用户按停止、agent 确认停住
之后那一轮确实结束了，照写；而"停不掉、只好断流"那条兜底路径下轮次还在 agent 那边
跑，那时候写一行结束时刻就是在撒谎，所以不写。判据是本地有没有 abort 掉这条流。

## 后果

- 新增 `POST /chat/inject`、`POST /chat/question`、`POST /chat/cancel`、
  `GET /chat/live-sessions` 四条代理路由；选项卡与审批卡共用同一套归属登记（别人的会话不许替他选）。
- 依赖 agent ≥ v1.16.3。老 agent 上：不发新事件 → 选项卡和追加回执不出现；
  `live-sessions` 拿不到 → 不显示闪烁标记；没有 `turn_times` → 历史会话不显示
  时刻。全部是"这一块不出现"，不是画一个编出来的值。
- E2E 见 `client/e2e/followups.mjs`（真实组件树 + 假 HTTP 层）。
