# ADR-0017 · 琉璃主题复用静谧的形状层，只加材质 / 高度 / 动效 / 排版

- **日期**：2026-08-21
- **状态**：已采纳

## 背景

第 19、20 套主题「琉璃」（`lucent-light` / `lucent-dark`）要做成"材质风"：
会浮起来的面是有厚度的玻璃，内容面是不透明的纸。

已有两套软风格主题：门道（`flat` 皮肤，线条直角）和静谧（`quiet` 皮肤，无边框
阅读风）。静谧那个文件里有 121 处规则，其中大半是踩出来的修正 —— 活动行差 1px、
焦点圈在圆角控件上露出四个直角、终端页平白多出 20px 内边距、去掉底座边框后正文
被输入框齐刷刷切一刀。

## 决策

**形状层复用静谧那一份文件，不复制。** `quiet-skin.css` 的选择器从
`html[data-skin="quiet"]` 加宽成 `html:is([data-skin="quiet"],[data-skin="lucent"])`，
琉璃在它之上叠一个只写增量的 `lucent-skin.css`。

配套四条：

1. **`data-skin` 仍然是两个值**，不是让琉璃复用 `"quiet"`。
2. **材质只发给真正浮在内容之上的面**，名单写死，不用通配符。
3. **排版是琉璃和静谧的主要分野**，不是配色。
4. **中文标题不做负字距；大字用轻字重、小字用重字重。**

## 理由

**为什么不复制一份形状层：**复制等于把那 121 条里的坑复制一份，然后只在其中一份里
修。加宽选择器是零成本的：`:is()` 的特异性取括号内最高的那个（属性选择器 0,1,0），
加上 `html` 正好还是 (0,1,1)，和原来的 `html[data-skin="quiet"]` **逐位相同** ——
这不是"应该没影响"，是可以证明的相等。已用改动前的 worktree 起第二台验证台，
静谧浅/深、门道、经典暗夜四套逐值 diff 确认一致。

**为什么还要两个 skin 值：**`quiet-skin.css` 里有一条
`* { backdrop-filter: none !important }`（静谧刻意关掉全部半透明）。琉璃的材质正是
靠 `backdrop-filter` 活的，同名就会被那条通配符**静默**扫死 —— 玻璃退化成一块半透明
色板，看着只是"有点淡"，没有任何报错。所以那一条是整个文件里唯一不共享的规则。

**为什么材质要写死名单：**`backdrop-filter` 模糊的是元素背后已经画好的东西。而在这套
布局里，桌面的侧栏 / 顶栏 / 输入底座都是 flex **流内**元素，彼此不重叠，背后只有 body
的纯色底 —— 给它们加模糊，模糊的是一块纯色，结果和填一个不透明色一模一样，只是白白
多出一个强制合成层。静谧当初把 19 处 `backdrop-filter` 全杀掉正是为这个。
所以只发给：账户菜单 / 全部工具 / 模态 / 确认框 / ⌘K / 快捷弹层 / toast /
**移动端（≤900px）侧栏**（它在那里是 `position:fixed`，真盖在内容上）。
桌面外壳改用色差 + 0.5px 高光边，**不假装那里有玻璃**。

**为什么排版才是主要分野：**第一版只做了材质、高度、动效和一套偏冷的调色板，形状和
排版都跟着静谧 —— 结果被维护者一眼判为"和静谧没什么变化，就是颜色差一点点"。
判断是对的：一套主题的辨识度，排版占的份额远大于色温。所以第二版把排版拉开：
正文 15→16px、正文默认字重 500、三级文字色整体压深（浅色 muted 88→62、faint
115→98），并把**成段落读**的地方（`.cc-answer` / `.md-p` / `.md-li` / `.tbl td`）
从次级色改回墨色 —— 次级色的用途是"这条信息次要"，不是"这是正文"。

**为什么中文标题不做负字距：**负字距是拉丁文大标题的做法，字母之间本来有空隙可以收；
汉字是满格方块，字面之间只剩很窄的侧边距，再收就是让它们互相挤，配粗体直接糊在一起。

**为什么大字反而用更轻的字重：**同一个字重，字号越大看起来越重（笔画等比放大，眼睛
感知的"黑度"却按面积走）。要让一屏上所有标题的**视觉重量**齐平，大字就得用更轻的
字重补偿。界线定在 21px：≥21px 用 500，<21px 用 600。这条线不能再往下挪 ——
Windows 上只有 Regular 和 Bold 两档可用（微软雅黑没有 Semibold 字面，CSS 字重匹配
遇到 600 会向上取到 700、遇到 500 会向下取到 400），16px 的小标题一旦掉到 Regular，
就和 16px 的正文完全一样了，没有中间档可退。

## 后果

- 加主题的成本没变（`lib/themes.ts` + `workbench.css` 变量块 + 自己的 tokens/skin），
  但**加一套"软风格"主题现在只需要写增量**。
- 静谧和琉璃的形状从此绑在一起：改 `quiet-skin.css` 会同时影响两套。这是有意的 ——
  两者的形状诉求本来就是同一个，分歧在材质、高度、动效和排版。
- `lib/appearance.ts` 的字重「标准」档改成 **400 = 不写 inline 覆盖**（和字体族的
  「跟随主题」档同一个约定）。以前它总是写死 inline `--ui-weight:400`，而 inline 压过
  一切 CSS，**主题因此永远没法定义自己的默认字重**。其余 17 套没定义它，
  `var(--ui-weight,400)` 回落 400，观感零变化。
- `workbench.css` 里还有 70 处硬编码 `box-shadow` 没换成 `--e0…--e4`。在换完之前，
  这些老组件在琉璃下仍然挂着自己的旧影子。有意分开做：混在一起改，出了问题分不清是
  主题的锅还是替换的锅。
- 输入底座没做成"对话流从下面滚过去"的玻璃条。那是这个界面里材质最能发挥的地方，
  但 `.cc-dock` 是流内的兄弟节点，要浮起来就得给 `.cc-thread` 补一个**等于底座实际
  高度**的 padding-bottom，而底座高度随输入行数变 —— 写死会挡住正文，那是功能回归。
  要做得对需要 JS 量高度。

### 踩到的坑（都是"静默不生效 / 静默错位"型）

- **CSS 选择器写错不报错。** 侧栏分组标题连写了三个不存在的类名
  （`.sb-group-title` / `.sb-sect-title` / `.sb-ws-title`），真实 markup 是
  `.sb-ws-head > span`（裸 span，没有类）。这类东西必须去 markup 里核实。
- **注释里的花括号和切点字符串会带偏主题注册表测试。** 在 `workbench.css` 的注释里
  写了一句带 `{}` 的示例、又提到了 `GLOBAL BASE`，同时踩中
  `test_theme_registry.py` 的花括号解析器和 `css.index()` 切点，`lucent-light` 的
  `--acc` 被解析成 `:root` 的默认值，看着像 CSS 写错了。测试两头都已硬化：解析前先剥
  注释、切点改用整行横幅。
- **提升特异性会顺手压死别人。** `html[data-skin=lucent] .ni{color:var(--t)}` (0,2,1)
  把「新建任务」的 `.ni-action{color:var(--acc)}` (0,1,0) 压成了黑字，整条侧栏唯一的
  主动作消失在一列同色文字里。
