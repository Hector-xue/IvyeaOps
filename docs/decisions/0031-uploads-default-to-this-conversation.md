# ADR-0031：上传的文件默认只属于这次对话

- 状态：已采纳
- 日期：2026-08-30

## 背景

任务台的「+」按钮，对非图片文件只有一条路：进知识库、建索引、永久留档，并在输入框里
代写一句「已把「X」加进知识库，可以直接问它的内容」。

用户的原话：

> 有些文件只是会话的时候用，并不需要纳入知识库啊。

知识库是长期资产 —— 它进检索、进引证、进覆盖率统计。把一份临时报价单塞进去，之后每次
检索都要从它旁边绕过去，而且用户还得自己去清。

## 决策

**默认改成「只带进这一轮对话」，入库变成一个显式动作。**

- 新增 `POST /api/ivyea-agent/session-files`：转调 agent 的 `/v1/files/extract` 抽正文，
  **不落盘、不建索引、不留档**，把字交给前端，随下一条消息作为 `attachment` 带下去。
- 输入框上方多一栏附件胶囊，每枚上面有「收进知识库」——**那才是入库的入口**。
- 不再往用户的输入框里代写文字。那是他的输入框；附件的状态该由附件栏自己表达。

## 理由

为什么抽取不在 ops 做：ops 只装了 pypdf / openpyxl，**没有 python-docx**，自己抽会漏
docx；而且两边各写一套抽取逻辑，同一份文件读出来的字迟早会不一样，"知识库里的这份"和
"这轮对话里的这份"内容对不上是最难查的那类 bug。

## 后果

- **行为变更**：老用户传文档不再自动入库。变的方向正是用户要的，入库的路也没消失，只是
  从"默认且唯一"变成"显式且并存"。
- **注入标记表必须两边同步**。`[用户附件` 要同时加进后端
  `console_sessions._INJECTION_MARKERS` 和前端 `lib/stripInjected.ts` —— 漏了哪一边，
  用户就会在那一边看到自己上传的整份 PDF 正文糊在气泡里。这份表分处两个文件，是这次
  最容易漏的一处。
- **会话记录里要看得见"我传过什么"**。只存文件名、不存正文（正文是给模型的几万字）。
  附图当初就是漏了这一步，用户的原话是「会话记录里面也没有展示我发送的图片」。
