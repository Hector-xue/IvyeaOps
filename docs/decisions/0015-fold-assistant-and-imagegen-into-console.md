# ADR-0015 · AI 问答与 AI 生图并入任务台

- **日期**：2026-08-17
- **状态**：已采纳

## 背景

侧边栏里长期挂着三个看起来相邻的板块：AI 问答、AI 生图、头程比价。任务台上线之后，
它们和任务台的关系需要重新算一遍。

盘完代码，三者情况完全不同：

- **AI 问答**早就不是独立实现了。它跑的就是任务台同一个 agent，会话存在同一个会话库里
  （`source=assistant`），差别只有两个开关：`use_tools:false` + `inject_retrieval:false`。
  它唯一比任务台多的东西，是 agent 掉线时会退回 `/api/assistant/chat` 的多 provider 兜底链。
- **AI 生图**的后端 `/api/assistant/image` 是全站唯一一条作图链路，任务台的 `image_generate`
  工具本来就直接调它。但闭环缺最后一步：任务台的正文渲染器只认 `**粗体**`/`` `代码` ``/`*斜体*`，
  **不认图片和链接** —— 出的图只会显示成一串裸 URL。另外图生图（拿用户的图当原图改）任务台
  做不到：附图走视觉旁路被读成文字，原图本身没有任何途径传给作图链路。
- **头程比价**根本不是 AI 功能：解析货代的 xls 报价单建索引，按仓库代码 + 重量段匹配、按价格
  排序。工具表里连一个 freight 工具都没有。

## 决策

**AI 问答、AI 生图两个板块删除，能力并入任务台；头程比价保留。**

删页面之前先补齐任务台缺的三样：

1. 正文渲染器支持 markdown 图片、链接和裸图片地址（协议白名单 http/https/data:image）
2. 附图换成 `ivyea-ref://` 短句柄传给 `image_generate`，打通图生图
3. agent 掉线时的纯聊兜底从 AI 问答页搬进任务台

`/assistant`、`/imagegen` 两条路由重定向到 `/console`，会话来源标记 `assistant` **保留**。

## 理由

**为什么不是直接删页面**：AI 问答删掉是零成本的（同一个 agent、同一个会话库），但 AI 生图
不是 —— 任务台虽然会自动调作图 API，出的图却看不见。先删页面等于把一个能用的功能换成一串
看不懂的 URL。能力补齐是删页面的前置条件，不是附赠品。

**为什么图不进模型**：图生图要把原图交给作图链路，最直白的做法是把 data URL 塞进
`image_generate` 的 `image_urls`。但一张图的 base64 有几百 KB，让它穿过模型的工具调用参数
是不可能的：光是抄一遍就能撑爆上下文，抄错一位图还废了。所以 ops 侧先把图落盘换成短句柄，
模型只经手 `ivyea-ref://<id>` 这一小串字符，服务端凭句柄取回原图。

**为什么不加「纯聊」开关**：这次的目标就是简化。代价说清楚 —— 写文案、问概念这类不需要工具
的问题，现在也会走带全套工具的重系统提示，更慢也更费 token。愿意的话后面再加不迟。

**为什么留着 `source=assistant`**：会话一条没动，历史里那些问答仍按来源筛选。把这个来源从类型
里删掉，等于让老对话在左栏筛不出来 —— 删的是入口，不是数据。

## 后果

- 侧边栏少两项；`/assistant`、`/imagegen` 的老书签不会 404，接回任务台。
- 后端 `server/app/routers/assistant.py` **一行没删**：兜底链和作图链路都在这个文件里，
  它是被任务台和 Listing、图片翻译共用的。删前端不等于删后端。
- 老 AI 问答页里那段「localStorage 历史一次性搬进会话库」必须跟着搬到任务台。漏了这一步的话，
  谁的浏览器没在删页面之前打开过 AI 问答，那份记录就永远进不来了。
- 清理句柄目录时**不能按 mtime 排序**：同一毫秒内落盘的几张图 mtime 会并列，谁被删看文件系统
  心情，用户刚贴的那张也可能被清掉，然后一调作图就是「附图引用已过期」。改成文件名自带定宽
  毫秒前缀，按名字排序。这个坑是被验证用例抓出来的（同一个用例第一次过、第二次挂）。
- 头程比价的正确走向是**让任务台能调它**（加一个只读 freight 工具），不是取代它。尚未做。
