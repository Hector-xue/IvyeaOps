# ADR-0002 · 放弃反向代理别人的 Dashboard，自己拥有整个前端

- **日期**：2026-05-03
- **状态**：已采纳
- **取代**：2026-04-30 的「用 Hermes Dashboard 作主页面」
- **依据**：Hermes 会话，2026-04-30 至 05-03

## 背景

自研的第一版 UI 被评价为「太丑了，直接弃用」，改成用 Hermes 自带的 Dashboard（9119 端口）
作主页面，8765 反向代理过去，自建板块（Claude web、服务器终端、监控）挂在它的侧边栏里。

结果一连三天都在修同一类问题：

- 自建板块的 URL 沿用上一个点击的板块，不会变成自己的路径
- 点了自建板块之后，再点原生板块没有任何反应
- 侧边栏高亮竖条同时出现两条，上一个不消失
- 自建板块的顶栏和原生板块的横线对不齐
- 原生板块点击会自动收起侧边栏，自建的不会

## 决策

不再反向代理。把需要的东西合并进自己的代码，前端完全自研自控。

作者原话：**「能不能不用反向代理，把 Dashboard 那些东西都合并到我自己的文件里面，以后
Dashboard 更新的话就从里面拉取更新的内容添加到我自己的文件里面」**。

## 理由

- 反向代理下「自己的板块」和「别人的板块」永远是两套路由、两套状态、两套样式，对齐成本无穷
- 视觉一致性做不到 —— 主题切换、间距、高亮都要跟着别人的实现走
- 出问题时排查链路太长，分不清是自己的 bug 还是代理的 bug

## 后果

- 短期成本高：所有板块要重做一遍
- 长期收益是决定性的 —— 后来的主题系统（16+ 套）、统一的板块框架、移动端适配、
  路由级懒加载，都建立在「前端是自己的」这个前提上
- 2026-06-03 把最后的 `cloudcli/ccui` 痕迹也清掉，统一改名 `agents`
