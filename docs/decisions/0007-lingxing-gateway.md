# ADR-0007 · 领星 ERP 走自建网关，写操作一律人工确认

- **日期**：2026-06-04
- **状态**：已采纳
- **依据**：当日 21 个 `feat(lingxing)` 提交（P0 → P4）

## 背景

要把领星 ERP 的广告数据接进工作台，做真正能动手的广告优化。这意味着 AI 有可能直接改动线上
广告活动的出价、预算和关键词 —— 动的是真钱。

调研发现：领星官方 MCP 里**没有广告写操作工具**（只有监控类），真正的广告链路是领星 OpenAPI，
需要自己做签名验签。

## 决策

自建一个网关，作为唯一咽喉。所有对领星的调用都从它过，网关承担五件事：

1. **密钥隔离** —— 凭据只存在网关一侧
2. **限流** —— 1 秒 1 次，硬限制
3. **读写双开关** —— 默认只读，写操作要显式打开
4. **三重复核** —— 写操作前由多个不同人设/不同模型分别复核
5. **审计与回滚** —— 每一次写都留痕，且可回退

分期落地：P0 网关骨架 → P1 只读数据层 → P2 周度建议（只分析不写）→ P3 受控写入（三重复核
+ 人工确认）→ P4 审计面板与熔断。

## 理由

- 「AI 直接改线上广告」这件事，出错的代价是真金白银，不能靠模型自觉
- 单一咽喉才能保证限流、审计、熔断这些约束无法被绕过
- 分期上线让每一层的信任都建立在前一层跑通之上

## 后果

- 广告优化后来演化成**确定性规则引擎 + LLM 复核**的组合，而不是让模型自由发挥：
  阈值、公式、护栏都写死在规则里，模型只负责复核和解释
- 保守阈值成为默认：否词需 ≥15 次点击且 0 转化，bid 单次调整 ≤15%，同一对象冷却 7 天
- 数据不够时**不动手**，这是硬规则
