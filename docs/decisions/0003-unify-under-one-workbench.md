# ADR-0003 · 所有 Web 能力收编到一个工作台

- **日期**：2026-05-09
- **状态**：已采纳
- **依据**：Hermes 会话，2026-05-09 11:38

## 背景

到 5 月上旬，服务器上并存着多个互不相干的 Web 服务：控制面板（8765）、claudecodeui、
skill-studio、ai-launcher、Amazon 工作台 MVP，各自占一个端口。作者已经需要问
「检查一下我这个服务器上现在都有哪些 web，给我总结罗列一下」才记得清。

## 决策

**「把我现有的所有 WEB 端都放在 8765 下面，然后给定一个主页面，再把所有下属页面的入口都
嵌入到主页面」**。

## 理由

- 多个端口意味着多套鉴权、多个书签、多处配置，安全面也大
- 这些能力服务的是同一个人、同一件事（Amazon 运营 + 服务器运维），本来就该在一起
- 只暴露一个端口，其余绑回环，是更好的安全姿态

## 后果

- IvyeaOps 作为「一个产品」而不是「一堆脚本」的概念在这天成立
- 确立了「侧边栏 + 板块」这个至今未变的骨架
- 后续新增能力的默认做法变成「加一个板块」，而不是「起一个新服务」
- 2026 年 7 月的服务器加固沿用同一原则：新服务一律绑 127.0.0.1，通过主入口鉴权后代理
