# ADR-0030：Agent 给用户看图，权限复用「工作区绑目录」

- 状态：已采纳
- 日期：2026-08-30

## 背景

Agent 此前只能用文字描述它截到的、跑出来的、读到的图。用户的问法是：Claude Code
的回复能带图片，CLI 里不显示但网页端显示得出来，我的 agent 能不能也这样。

渲染这一半其实早就有了 —— `lib/reportFormat.tsx` 会把正文里的 `![](…)` 渲染成图，
`image_generate` 一直在用这条路。缺的只是"把一个本地文件变成一个网页取得到的地址"。

约束是：agent serve **没有任何二进制出口**（`/v1/*` 全是 JSON），所以它自己产不出
浏览器能取的 URL。这个能力只能做在 ops 这边。

## 决策

新增 ops 工具 `show_image(path, caption)`。ops 读文件、复制进独立的会话图库、把站内
地址回给模型，模型把 `![](地址)` 写进正文。**图片本体不进模型**，和用户贴图那条路一致。

**允许读取的目录 = 已绑定目录的工作区，不另发明一套授权。**

## 理由

这是 ops 工具面上**第一个按路径读文件的工具**（此前一个文件读原语都没有），所以边界
必须一次划清。可选的做法有三种：

1. 不限路径 —— 否掉。ops 进程权限高，等于把整个文件系统交给模型的一个参数。
2. 新造一套"允许 show_image 读的目录"配置 —— 否掉。同一件事有两套授权，用户要在两个
   地方维护，迟早对不上，而且没有人会去读第二套的说明。
3. **复用「给工作区绑目录」** —— 采纳。那本来就是这套系统里管 Agent 文件访问面的那个
   动作（`create_workspace` 里写着：绑了之后 Agent 的相对路径读写都落在那里，等于给了
   一片文件系统的访问面，和 MCP 的 stdio command 是同一类授权，仅限管理员）。
   于是规则变成一句话：**Agent 能读写的地方，就是它能给你看图的地方。** 没有新增访问面。

代价是：没绑目录的工作区（比如默认工作区）用不了这个工具，会收到一句"去给工作区绑个
目录"。这是有意的 —— agent 那时用的是自己的进程 cwd，而那是个 ops 无从知道、也从没被
授权过的目录，宁可让工具报错，也不能自己猜一个路径放行。

## 后果

三道闸缺一不可，都是实测验过的：

- **先 `resolve()` 再判包含**。只比字符串前缀的话，工作区里放一条指向 `/etc` 的软链就
  穿过去了。
- **按文件头判是不是图片，不看扩展名**。扩展名是模型说了算的，只看后缀等于让模型决定
  "什么算图片"，那这个出口就成了任意文件外泄通道。
- **SVG 明确不收**。它是文本、能带 `<script>`，而这个出口是同源的。要展示矢量图先转 png。

**存储和 `imagegen-refs` 分开。** 那个库是"用户刚贴的原图"的中转站，只留最近 200 张、
转得飞快；而这里存的是**已经写进会话存档的图**（`![](…)` 会一直躺在会话记录里）。混进
那个库的话，几天前的会话打开就是一排碎图，而正文还在言之凿凿地描述它们。

**出口地址带扩展名**（`<id>.png`）。模型很常把地址单甩一行，那条路（`looksLikeImage`）
是按后缀判要不要当成图的。两种写法都验过：`![]()` 和独占一行的裸地址都渲染成图；句子
中间的内联地址是纯文本，所以工具描述里明确要求写成图片语法。

## 补充：终端那一半

IvyeaAgent 侧也加了一个同名内置工具 `show_image`，**一个工具名两种形态**：

- 嵌在 IvyeaOps 里（serve）→ 经 ops 工具桥委托给本文这个实现。权限边界只有这一处，
  agent 那边不自己开一套。
- 终端（CLI）→ 没有浏览器可送、也没有出口可挂，所以只做一件诚实的事：确认这确实是
  一张图、报出绝对路径。用户看不到画面，但知道是哪张图。

不做成两个工具名，是因为模型不该为了"我现在跑在哪"去挑工具 —— 那种分支迟早挑错。

一个坑：CLI 分支**绝不能往 stdout 打字**。`-p --output-format stream-json` 下 stdout
是协议通道，多打一行就把调用方的解析打断了。要说的话一律走返回值。
