# ADR-0013 · 自动链路全面去 Hermes，统一走 IvyeaAgent

- **日期**：2026-08-06
- **状态**：已采纳
- **依据**：提交 `refactor(ai): 自动链路全面去 hermes，统一走 ivyea-agent`（v1.1.116, PR #102）

## 背景

到 8 月，IvyeaAgent 已经具备工作台需要的全部能力，但很多自动链路（审计、市场调研、打法生成、
资讯汇总）仍然默认走 Hermes。Hermes 还带来两个运维负担：开机自启多条路径、bun 进程常驻。

## 决策

所有自动链路改走 IvyeaAgent。Hermes 不再是任何自动流程的默认。

## 理由

- 减少一个重量级外部依赖，开源用户少装一样东西
- 自己的 agent 出问题能自己修，外部 CLI 只能等上游
- 统一链路后，成本统计、审计、可观测性才有单一口径

## 后果

**最重要的一条教训**：改代码里的默认值不够 —— **真正决定走哪条链路的是数据库里存的配置**。
本机 DB 里存的还是 hermes，代码默认改了也没用，必须同时迁移配置。

连带修掉的问题：

- sellersprite MCP 的 stdio server 不支持 NDJSON 分帧，导致 agent 一开工具就挂死
- 多步 agent 的正文可能出现在较早一轮，只取最后一轮会只拿到一句收尾，要回捞完整报告

另外：做性能/质量对比时，**必须同配置**才有意义，否则比的是配置不是引擎。
