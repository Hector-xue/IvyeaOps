# ADR-0034 · 自定义 MCP 数据源做成「注册表 + 映射配置」，内置三家保持写死

- **日期**：2026-09-10
- **状态**：已采纳
- **依据**：2026-09-10 会话

## 背景

工作台的市场数据源原本只有三家写死的：Sorftime、卖家精灵、SIF。它们各有一个专用的
后端服务模块（`sorftime_service` / `sellersprite_service` / `sif_service`），工具名、
入参、返回字段全部按各自服务器的真实行为硬编码；前端的可选清单写在
`client/src/lib/dataSource.ts` 的常量里，后端的合法值写在各路由的 `_DATA_SOURCES`
集合里。

问题有两个：

1. 开源之后，没有这三家账号的人一个板块都点不亮。
2. 已经存在的 `~/.ivyea/mcp.json` 注册表只让 **对话侧** 的 IvyeaAgent 用得上自定义
   MCP —— 首页监控、市场调研、打法推荐这三个板块走的是上面那条写死的管道，用户加了
   自己的 MCP 也不会出现在数据源下拉里。

## 决策

新增一类**配置驱动**的数据源：用户填一份「MCP 端点 + 鉴权 + 工具名 + 字段映射」，
系统在运行时把它翻译成工作台内部那套 provider-neutral 的返回结构。

- 自定义源 id 一律带 `custom:` 前缀，与内置 id 永不撞名。
- 内置三家的代码路径**一行不改**：分发点上先查自定义注册表，命中才短路，否则原样走
  老分支。
- 契约不另起一套 —— 直接采用 `sellersprite_service` 已经实现的那十个能力函数的签名和
  返回结构。它本来就是为了让首页各板块换源无感而写的，等于一份现成的适配器契约。
- 配置存 `hub_settings.custom_data_sources`（JSON 数组），其中的凭据由
  `custom_source_registry` 自己调 `core/secrets` 加解密。

## 理由

**为什么不先把 61 处 `if source == "sellersprite"` 重构成统一的 provider 接口。**
那是更干净的终局，但它会动到三家内置源的每一个调用点。内置源是当前唯一在生产里跑的
链路，为了加一个新能力去改它们，收益和风险不成比例。先加、后收口，随时可以再做，
反过来不行。

**为什么契约照抄 sellersprite 而不是新设计一套。** 首页卡片、图表、告警读的是
`title / price / bsr / est_sales …` 这一组固定字段名，前端还写了
`monthly_search_volume ?? 月搜索量 ?? searchVolume` 这样的多别名兜底。任何"更合理"的
新字段名都得同步改一遍消费方，而消费方正是最容易漏的地方。

**为什么凭据要在注册表里自己加密。** `hub_settings` 是**按字段名**决定加不加密的
（`is_secret_key` 匹配 key/secret/token 等词），而 `custom_data_sources` 这个名字一个
都不命中 —— 整块 JSON 会明文落盘，里面却装着 API key。所以加解密收口在注册表的存取
函数里，不能指望上层。

**为什么不做"自动嗅探字段"。** 试过在脑子里推演：不同服务器对同一概念的字段名差异
太大（`reviews` / `ratings` / `reviewCount`），猜错的代价是**静默出错** —— 卡片照常
渲染，数字是空的或者是别的指标。改成显式映射 + 一个「试跑」按钮告诉用户"映射出了
几个字段"，错了当场看得见。多写的那点配置换的是这个。

## 补充决策：映射由系统推断，不由用户填（2026-09-10 当天修正）

第一版把映射编辑器做成了默认界面 —— 十项能力、每项一组字段路径输入框。等于把内部
的映射 DSL 原样甩给用户。维护者的原话是"感觉需要设置的东西太多了，我只想配置好，
然后在对应的板块下拉选择它就能直接用"。这是设计错误，当天改掉。

改成：默认只填端点和密钥，点「自动配置」。后端
（`services/custom_source_autoconfig`）做三件事：

1. `tools/list` 拿工具清单和入参 schema；
2. 按工具名/描述给每项能力挑最像的工具，按 schema 的参数名推出入参模板
   （`asin`→`{asin}`、`site`/`amz_site`/`country`→`{marketplace}`…，支持一层
   `{"request": {...}}` 嵌套）；
3. **拿样例真调一次**，把返回摊平成「路径 → 值」，再按别名表把对方的字段名对到
   工作台的字段名上。

关键是第 3 步为什么必须真调：绝大多数 MCP 服务器不给 outputSchema，光看 schema
推不出返回字段。而猜错的代价是**静默出错** —— 卡片照常渲染，数字是空的。真调一次，
映射是从真实响应里读出来的；对不上就在报告里明说"这项没配成"，不假装成功。

配套的两条判据：
- **数值型目标字段要过类型检查**：名字像但值是 `"面议"` 这种串的，宁可不映射。
- **浅路径优先**：同名字段出现在多层时，外层几乎总是主字段。

手工编辑器保留，但降级为「高级设置」折叠区 —— 它是自动推断出错时的补救口，
不是常规路径。

## 再修正：把"用户要填的"压到只剩端点和密钥（同日第二轮）

上一轮把映射自动化之后，界面上还剩三样要用户操作的东西，维护者的反馈仍然是
"还是很费劲"。逐条看，三样都不该问：

- **鉴权方式 + 参数名**。常见传法就那么几种，挨个试一遍就知道了
  （`custom_source_mcp.detect_auth`）。注意验证**必须用 `tools/call`**：大量
  服务器的 `tools/list` 不鉴权，拿它当判据的话八种写法会全部"成功"，等于没测。
- **在哪些板块出现**。这是**结果**不是输入 —— 配了什么能力就在什么板块出现
  （`derive_surfaces`）。上一版让用户自己勾，还加了条"勾了板块必须配对应能力"的
  校验，结果是：勾完板块还没配能力时，连「自动配置」按钮本身都被这条校验拦死了
  （它走同一条 `hydrate → validate`）。**用输入去校验结果，就会锁死通往结果的路。**
- **名称和标识 id**。从端点域名推一个即可，用户改不改随意。

配套把报错里的内部标识符全换成中文能力名 —— `勾选了「market」板块就必须配置能力：
keyword_pipeline` 这种句子，对着看的人一个词都不认识。

最终默认视图：三个输入框（端点、密钥、名称）+ 一个按钮。其余全部收进「高级设置」。

## 第三轮：把"没配上"的原因说到能行动（同日）

维护者看着高级设置里那排没勾上的能力问："这些没有自动选择的，是这个 MCP 没有这些
工具吗？" —— 问得对，因为当时只有一句 `没有找到合适的工具`，它把三种完全不同的
情况糊在一起：

| 实际情况 | 用户该做什么 |
|---|---|
| 这台服务器真没有吃 ASIN/关键词的工具 | 没辙，这项功能就是用不了 |
| 有，但必填参数认不出该填什么 | 去高级设置手写入参模板 |
| **有，参数也没问题，只是名字和描述里没有我认得的词** | **自己指一个工具就行** |

第三种最常见也最亏 —— 报成"没有"会让人以为服务器不支持，直接放弃。现在每种给
不同的 `reason` 和人话说明，第三种还把工具名列出来，点一下走 `/data-sources/remap`
用那个工具重新推断映射。

**分寸在这里**：让人挑工具是合理的（他知道自己的数据源哪个接口是干什么的），让人
逐个填字段路径不是（那是机器该从真实返回里读出来的）。所以候选按钮只让用户指工具，
映射照旧自动推断，指错了会明说"这个工具的返回里认不出需要的字段"，不生成一份全空的
映射假装配好了。

原因显示在**每一行能力上**，不是只印在上面的报告里 —— 用户是在这排清单上产生疑问的，
答案就得在这里。

## 后果

- 新增能力时，契约的唯一真相在 `custom_source_registry.CAPABILITIES` 和
  `custom_source_provider` 的同名方法上，两边要一起改；`sellersprite_service` 的同名
  函数是参照物，不要让三者分叉。
- 半配置的数据源是**允许**的状态：没配的能力返回该能力契约里的"空 + error"结构，
  卡片渲染出一行说明而不是 500。设计目标是"能用的部分先用起来"。
- 日粒度类目历史（`category_report_from_history`）没有通用等价物，自定义源和卖家精灵
  一样明确不支持，走「导入历史」按月回填。
- 踩到的坑，都已经落在代码注释和测试里：
  - **信封形态**：`{doc,data}`（Sorftime）、`{code,message,data}`（卖家精灵）、裸
    `{data}` 是同一件事，按"除 data 外全是信封字段"这条列举法统一拆。
  - **失败装在成功响应里**：HTTP 200 + `isError`、`code != OK`、或者干脆一句
    "Please specify the site to query"。不识别就会把报错当数据喂给模型，模型照着编。
  - **整值占位符要保类型**：`"{top_n}"` 渲染成字符串 `"30"` 会被不少服务器静默忽略。
  - **`tools/list` 通常不鉴权**：能列出工具 ≠ 密钥有效，所以「探测」成功不作数，
    密钥要靠「试跑」验证。界面上把这句写出来了。
