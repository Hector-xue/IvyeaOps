# IvyeaOps 使用手册（各板块说明）

本手册逐个说明 IvyeaOps 控制台的各功能板块：用途、怎么用、需要哪些配置。
安装与部署见 [`INSTALL.md`](INSTALL.md)，配置项参考见 [`CONFIG.md`](CONFIG.md)，
外部集成见 [`INTEGRATIONS.md`](INTEGRATIONS.md)。

> **标注说明**：带 🔒 的板块默认仅管理员可见，可在「用户管理」按板块授权给普通用户。

---

## 0. 先理解两个全局概念

几乎所有 AI 板块都共用同一套机制，先看懂这两点能少踩很多坑。

### 0.1 AI 降级链（所有文本 AI 的统一出口）

需要"写文本"的板块（市场调研、打法、Listing、Skill、资讯…）都走同一条**降级链**，按顺序尝试，前一个失败自动切下一个：

```
全局兜底大模型 → DeepSeek → Codex → Claude
```

- **IvyeaAgent** 是 IvyeaOps 内置 Agent，负责右下角会话、知识库和本地检索。
- **Codex / Claude / Hermes** 是可选外部 Agent CLI；新部署不再要求安装 Hermes/Ollama。
- **全局兜底大模型**是你在「系统配置 → 应用模型 → 全局兜底大模型」里填的任意 OpenAI 兼容模型（DeepSeek / OpenAI / OpenRouter / Kimi / 自定义…）。
  **只要配好它，主要 AI 功能即可开箱使用**。
- 链的顺序可在「系统配置 → 智能体 → AI 提供商顺序」(`text_ai_providers`) 自定义。
- 健康状态见「系统配置 → 健康检查 → AI · 文本链可用 / 全局兜底 / 视觉识别」。

### 0.2 数据源（市场数据来自哪里）

首页 / 市场调研 / 打法推荐 顶部都有一个**数据源选择器**：

- **Sorftime** —— 当前唯一已接入的市场数据后端（销量、关键词、广告位、类目排行等）。需在「系统配置 → 数据源」填 `sorftime_key`。
- **SIF / 卖家精灵** —— 已预留配置位，数据客户端尚在开发中，界面标注「即将支持」，选中会显示占位说明。

## 〇、任务台（Agent 优先的新外壳）

改造后 IvyeaOps 的默认入口是**任务台**，不再是"25 个板块自己挑一个进"。
思路是：**说一句需求，Agent 自己挑技能、调板块能力拿真实数据、给结论**。
原来的板块一个没少，都收在左栏的「更多工具」里，只是从"你要自己找的入口"
变成了"Agent 可以调用的能力"。

### 任务台
入口 `/console`（登录后默认落地）

- **一句话派活**：不用想"这事该去哪个板块"。不知道说什么就点场景芯片。
- **过程说人话**：会看到「已匹配 N 项技能 · 用时 X 秒」、调了哪个板块能力、耗时多少，
  而不是一个不动的转圈。规划汇报类的步骤会自动折起来，不淹没真正干活的那几步。
- **输入框下面那一行是真开关**，不是装饰：
  - **工作区** —— 会话分组；管理员还可以给工作区绑一个目录，Agent 的文件操作就在那里
  - **审批档位**（三档）——
    `只读`（默认，只分析只给方案，绝不动线上数据）/
    `审批放行`（要写入时停下来问你，确认一条执行一条）/
    `完全放行`（这一轮一次性授权，写操作直接执行，不再逐条确认）
  - **模型** —— 只显示当前主脑，点击跳「系统配置」切换（模型是全局配置，不按轮次覆盖）
  - 技能不用手动挑：按你说的话自动匹配。要钉死某个技能时用 `/` 命令。
- **默认不写、写要点头**：只读是默认档；切到「审批放行」后，Agent 要改线上数据时会弹
  确认卡，没点确认就**不会落写**。「完全放行」是你主动一次性授权这一轮 —— 它在界面上
  是红色芯片，就是为了不让人误开着它。
- **上下文进度条**：输入框下面那条细进度条 = 这条会话把模型的上下文窗口用掉多少了。
  点开看细账（系统提示词 / 工具 / 对话消息各占多少）。数是估算值。

### 能力市场
入口 `/capabilities`

Agent 能用什么，摊在这一页：**技能 / 社区市场 / MCP / 智能体 / 授权**。
原「Skill 中心」已并入这里的「技能」标签。

**技能**标签下是同一批技能上的三个动作，用分段控件切：

| 分段 | 干什么 |
|---|---|
| 运行 | Agent 内置技能（点「在任务台用」）+ 自己的技能（填参数直接执行，带运行历史） |
| 创建 | 想法工坊：一句话需求 → 多阶段流水线（理解→规划→复核→优化→生成→自检修复）产出 SKILL.md |
| 管理 | 编辑技能文件、快照与回收站、从 GitHub 导入，以及技能库挂载状态 |

「运行 / 创建 / 管理」需要「技能」这项授权（管理员在用户管理里授予）；没有的话只看得到
Agent 内置技能。老书签 `/skill-hub` 会自动跳到这里。

MCP 那边仍有一件长期容易混的事：**它有两套注册表**——`~/.ivyea/mcp.json`（决定 Agent 能连
哪些数据源）和 Claude Code 的 `~/.claude.json`，页面按来源分区标明。技能这边现在只有一套：
`{数据目录}/skills` 原地挂给 Agent，amazon 分类的改完即时生效。

给 MCP 绑 stdio `command`、给工作区绑目录都**仅限管理员**——那等于给 Agent 一片执行/文件访问面。

### 定时任务 🔒
入口 `/schedules`

到点让 Agent 自己跑一轮，结果留在运行历史里。常用节奏有预设，也能写 cron
（保存前会告诉你接下来几次什么时候跑，按**服务器本地时区**）。

> **定时任务始终只读。** 没人在屏幕前的时候，Agent 只会巡检、分析、把要改的列清楚，
> 不会真的动线上数据——"自动批准写操作"这件事我们刻意没有做成开关。
> 要落地，看完结果再去对应板块执行。

### 经典外壳（应急快照）

顶栏有个 `▤ 经典 / ◆ 任务台` 开关。切到**经典**会完整回到改造前的分组侧边栏，
25 个板块原样都在——它的定位是**出问题时的退路**，不是并行的第二套界面：

- 经典外壳里**看不到**任务台 / 能力市场 / 定时任务（这是预期行为，不是 bug）
- 它只修 bug，不再加新功能
- 切换只影响你自己的浏览器（存在本地），不影响别人

## 一、选品与调研

### 首页（运营驾驶舱）
入口 `/dashboard` · 数据源驱动、**不调用大模型**

每日盯盘面板，5 个标签页：
- **大盘流量** / **关键词** / **竞品监控** / **自有 ASIN** / **类目大盘**

用法：右上角选**站点**和**数据源** → 切到对应标签 → 添加要监控的 ASIN / 关键词 / 类目 → 查看销量、排名、流量变化与告警。切换数据源会重新加载全部数据。

需要配置：`sorftime_key`。

### 市场调研 🔒不需要（对所有用户开放分析，但 AI 强制走 HTTP）
入口 `/market`

输入**关键词**或 **ASIN**，一键生成一份结构化的亚马逊市场调研报告（市场规模、竞争格局、机会与风险、SWOT、行动清单）。

用法：选「关键词/ASIN」模式 → 输入 → 选数据源(Sorftime)与站点 → **生成报告**。报告下方有：
- **深入分析**：选一个分析角度（市场诊断 / ASIN 深析 / 广告策略）+ 一个智能体，把整份报告作为文档带入「智能体会话」继续追问。
- **历史记录**：自动保存，可随时载入或导出（MD / HTML）。

AI 走标准降级链（应用模型优先）。需要配置：`sorftime_key` + 至少一个可用文本 AI。

### 打法推荐
入口 `/playbook`

输入产品词/竞品 ASIN + **目标售价**（必填）+ 成本（选填），生成一份纯白帽站内打法手册（选品定价、关键词布局、广告结构、节奏排期、广告批量表）。

用法同市场调研，出报告后同样有**深入分析**（落地执行 / 广告细化 / 风险推演）和历史记录、`.csv` 广告批量表导出。

### 分析工具 🔒
入口 `/tools`

三组工具：
1. **ASIN 深度审计**：输入竞品 ASIN，由 Agent（hermes + MCP 抓数据）生成 COSMO/Rufus 维度的审计报告。出报告后有深入分析（Listing 优化 / 竞品策略 / 广告布局）。
2. **广告 search-term 审计**：上传 SP/SB/SD 搜索词报告 xlsx，做根因分析（竞价 / 关键词 / 结构），出报告后有深入分析。
3. **深入分析小工具**：关键词竞争、竞品流量、流量诊断、评论聚类、Listing 改写。其中「评论聚类」「Listing 改写」产出报告后也可一键带入智能体会话深挖。

> ASIN 审计 / 广告审计需要能调工具的本地 Agent（hermes）；纯兜底文本模型无法替代抓数据。

## 二、内容生产

### Listing 工作台 🔒
入口 `/listing`

从竞品 ASIN 到整套 Listing 文案 + 成品套图的流水线：

1. **采集**：抓取竞品文案与图片。**零安装、零密钥、零 Docker**，三级自动降级：
   - **本机 curl 直连 Amazon**（主路径，Windows 10/11 与各 Linux 都自带 curl）——
     直接读商品页内联 JSON，拿**完整主图组（最多 7 张轮播主图）**。
   - 被反爬拦截时**自动改用本机浏览器无头渲染**（Chrome / Edge / Chromium 任意一个，
     Windows 自带 Edge），同样能拿完整主图组。
   - 两条都没过才**回退 Sorftime**，但 **Sorftime 只返回 1 张白底主图**——
     此时 Listing 板块会提示你重试一次（反爬多是临时的）。
2. **补充产品信息 / 上传自有图片**。
3. **AI 智能分析**：分析采集文案，并对**采集 + 上传的所有图片做视觉识别**（分批，覆盖每一张），提取「图片卖点清单」。
4. **生成文案**：标题 / 五点 / 搜索词 / A+，都基于上一步的卖点。
5. **套图分镜**：以白底图（上传优先，其次通过白底检测的采集主图）为**产品真值**，按销售叙事排出
   主图 / 核心利益 / 真实使用 / 细节 / 规格 / 对比 / 包装等分镜，服务端编译提示词后**图文一次直出**
   （画面与英文文案由图片模型同时写入像素，不再本地叠字）。A+ 宽幅按原生比例出图。
6. **质检与交付**：逐张做技术质量 / 产品一致性 / 文字逐字准确性质检（发现错字或产品失真自动重画一次），
   整套再查色系与叙事一致性；每张需**人工勾选「已核对产品一致性」**后才进入可交付状态，未复核的导出标 `DRAFT`。
   单张最多保留 8 个历史版本，可随时「重做这张」。
7. **导出**：整套 ZIP 打包在「③ 视觉套图」里；单张可下 **PNG 或 PSD** —— PSD 为两层
   （成图 + 默认隐藏的产品真值白底图），可直接进 Photoshop 二次加工。画面上的文字是图片模型
   写进像素的，因此 PSD 里**没有可编辑的文字层**。

方法论与硬性约束详见 [`listing-visual-studio.md`](listing-visual-studio.md)。

所有 AI 步骤走标准降级链；图片识别与成图质检需要在「系统配置 → 视觉复核模型」配好**视觉大模型**
（硅基流动 Qwen3-VL / 阿里云百炼 qwen-vl / 智谱 GLM-4V / OpenAI GPT-4o 系等；**Apimart 只生图、无视觉，不能用于此**）。采集不需要配置任何东西。

### 问答与作图
入口 `/console`（任务台）

**这两件事不再是独立板块**，直接在任务台说就行：

- **问答/写作** —— 不需要工具的问题直接问。IvyeaAgent 没起来时自动退回「全局兜底大模型」
  (`assistant_*`) 的多 provider 链，那一轮会标明走的是备用通道（无工具、不进会话库）。
- **作图** —— 说「画一张主图」即可，任务台会自动调生图链路（默认 Apimart `gpt-image-2`，
  可在「系统配置 → 图片生成服务」自定义模型/Key/Base），出的图直接显示在回答里。
- **改图** —— 贴一张图再说要怎么改，就是在你这张图上改（真·图生图，保留原图内容）。
  点回答里的任意一张图，就把它收进输入框当下一轮的原图，可以一轮轮改下去。

老入口 `/assistant`、`/imagegen` 会自动跳到任务台；过去在 AI 问答里的历史会话仍在左栏，
可按「AI 问答」来源筛选。

## 三、运营数据

### 领星 ERP 🔒
入口 `/lingxing`

接入领星 ERP（官方 MCP / OpenAPI）查看与（受控地）操作店铺数据、广告等。配置较多，**详见专门指南** [`lingxing-erp-guide.md`](lingxing-erp-guide.md)。

### 头程比价
入口 `/freight` · **不使用 AI**

上传货代头程报价 Excel，自动解析成统一表格做横向比价（纯解析，无大模型）。

### 资讯 🔒
入口 `/news`

每日「AI 行业 + 亚马逊卖家」资讯摘要。点**立即刷新**即现场抓取 RSS 源 + 用标准 AI 链生成中文摘要（重要度、官方标记、标签），无需任何外部 cron，开箱即用。

可在「系统配置」用 `news_feeds` 自定义 RSS 源（每行 `url | 来源名 | 分类`，分类 = `ai_industry` 或 `amazon_seller`）。需要至少一个可用文本 AI。

## 四、智能体与知识

### 智能体会话 🔒
入口 `/agents`

右下角常驻 **IvyeaAgent** 是默认会话入口，支持对话、知识库上传、搜索和状态检查。它会自动连接本地 `ivyea serve`，服务未启动时 IvyeaOps 会尝试拉起。

`/agents` 保留外部 Agent CLI（Claude Code / Hermes / Codex…）的完整会话界面（claudecodeui 原生移植）：多会话、流式输出、工具可视化、文件管理（含**上传文件，最大 300MB**）、resume 等。外部 CLI 是可选增强项。

### IvyeaAgent 知识库
入口：右下角 IvyeaAgent → 知识库

支持上传 Markdown / 文本 / 常见文档，先生成导入草稿，再确认写入 `~/.ivyea/knowledge`；也可以直接搜索知识卡和最近上传文件。

完整治理入口：`/brain?tab=governance`。页面提供官方来源变更审核、覆盖矩阵、知识/来源时效、持续质量评测、冲突风险和授权账户证据导入。管理员身份由 IvyeaOps 会话确定，并使用本地 Agent token 对审核断言签名；批准不会自动发布，未验证批准也不能进入发布草案。发布前必须查看官方 diff、编辑知识正文、生成草案 diff，再二次确认，结果会关联 change-event/source-hash 并写入审计台账。

“账户证据”标签支持账户健康、Listing、注册合规、费用、税务、结算、退货/SAFE-T 和品牌保护等文本证据。必须勾选本地处理授权与数据权利确认；系统不保存原始文件，邮箱、电话、地址、证件、银行和税号会脱敏，账户/order/case/claim/settlement/transaction 等标识只保留哈希引用。浏览器闭环可用 `cd client && npm run test:e2e:knowledge` 验证。

`/brain` 的对话、上传、搜索、页面等其他标签仍走尚未迁完的旧兼容工作流，读的是 `brain_root`（默认 `~/brain`）下的文件。

## 五、运维与管理

### 服务器终端 🔒
入口 `/terminal`

浏览器内的真实 PTY 终端，直接在服务器上敲命令；支持会话快照。仅管理员，谨慎授权。

### 服务器监控 🔒
入口 `/servmon`

查看服务器 CPU / 内存 / 磁盘 / 进程占用，可对高占用进程执行停止（带影响提示与二次确认）。

### 用户管理 🔒
入口 `/users`

多用户与 RBAC：新增/禁用用户、重置密码、**按板块授权**（上面带 🔒 的板块默认仅管理员，可在此逐项开放给指定用户）。

### 系统配置 🔒
入口 `/hub-settings`

全站配置中心：
- **数据源**：Sorftime / SIF / 卖家精灵 Key（带连通性测试）。
- **大模型**：Hermes 主模型 + Fallback 模型。
- **应用模型**：**全局兜底大模型（兼任务台纯聊兜底）** + 图片生成服务。
- **智能体**：hermes/codex/claude 路径、AI 提供商顺序、自动修复开关。
- **飞书 / Lark 通知**、**高级 / 运维**。
- **健康检查**：一眼看清各服务与 **AI 链就绪状态**（文本链 / 全局兜底 / 视觉）。

首次使用建议先走一遍**首启向导**（含「全局兜底大模型」一步），即可让全站 AI 立即可用。
